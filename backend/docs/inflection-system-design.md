# 拐点与锚定物识别系统设计

## 1. 文档信息

- 状态：V1 已实现，真实数据接入与回测待完成
- 更新日期：2026-07-19
- 代码位置：`backend/internal/strategy/inflection/`
- 评估接口：`POST /api/v1/strategy/inflections/evaluate`
- 配套思路文档：[`inflection-system-thinking.md`](./inflection-system-thinking.md)
- 字段和请求示例：[`inflection-engine.md`](./inflection-engine.md)

## 2. 目标

把会议纪要中的“拐点买入”转换成一套可解释、可回放、可测试的规则引擎，回答以下问题：

1. 当前市场、板块或个股是否处于拐点候选状态？
2. 旧赚钱效应锚和旧负反馈锚分别是谁？
3. 旧锚的走弱是主动走弱还是被环境拖累？
4. 是否出现了能够承接流动性的新标的？
5. 当前更接近大拐点、小拐点，还是没有信号？
6. 信号只是提前预期，还是已经满足确认条件？
7. 结论由哪些证据、权重和风险共同产生？

## 3. 非目标

V1 不负责：

- 自动下单；
- 给出收益保证；
- 把锚点直接解释成买入对象；
- 处理完整的T+1成交和卖出模拟；
- 模拟一字板排队、跌停卖不出、滑点、费用和容量；
- 自动从实时行情中构造全部输入字段；
- 用单次成功案例证明策略有效。

## 4. 核心关系

```text
旧共识锚失效或释放流动性
            |
            v
      新承接物主动出现
            ^
            |
环境锚负责判断主动/被动、局部/整体
```

大拐点要求旧锚出清、环境转折、新承接物主动三个部分同时具有较强证据。

小拐点允许只有局部裂缝和提前尝试，但必须明确标记其不确定性。

## 5. 系统架构

```text
providers / collectors
  - 指数与个股行情
  - 分钟K线和VWAP
  - 涨停/跌停/炸板事件
  - 市场宽度
  - 板块成分与跟随关系
  - 昨日涨停次日表现
            |
            v
feature normalization
  - 辨识度特征 0-100
  - 相对环境收益
  - 市场压力
  - 负反馈释放
            |
            v
inflection.Engine
  - 候选对象评分
  - 每类锚点选择
  - 主动/被动强弱
  - 大拐点判定
  - 小拐点判定
  - 证据与风险输出
            |
            v
HTTP API / history store / frontend
```

V1 已实现 `inflection.Engine` 和 HTTP 评估接口。数据采集、历史存储和页面尚未接通。

## 6. 领域模型

### 6.1 观察范围 `Scope`

| 值 | 含义 |
| --- | --- |
| `market` | 全市场或指数级别 |
| `sector` | 板块、题材或风格级别 |
| `stock` | 单一个股相对自身地位的级别 |

所有锚定和拐点判断都必须先确定范围。不同范围的数据不能直接混为同一个结论。

### 6.2 锚点类型 `AnchorKind`

| 值 | 作用 | 是否必然是交易对象 |
| --- | --- | --- |
| `old_profit` | 代表上一阶段赚钱效应是否仍然有效 | 否 |
| `old_negative` | 代表上一周期负反馈是否充分释放 | 否 |
| `new_carrier` | 代表流动性正在尝试流入的新方向 | 可能 |

环境锚由 `MarketSnapshot` 表示，不作为一只普通候选股票参与竞争。

预期锚由候选对象的 `expectation_gap_percent` 表示。负值代表实际表现低于买入时赋予的预期。

### 6.3 候选对象 `CandidateSnapshot`

候选对象包含：

- 身份：代码、名称、锚点类型、观察范围；
- 辨识度：高度、关注度、持续性、影响力、抗跌性；
- 相对表现：个股、板块、市场收益；
- 盘中行为：VWAP距离、涨停、跌停、炸板；
- 预期验证：实际表现与预期之间的差；
- 流动性：成交额相对历史水平；
- 共振：同板块跟随数量；
- 旧周期出清：连续跌停、三日回撤、跌停打开；
- 个股修复：上一状态是否被判定为被动走弱。

### 6.4 环境快照 `MarketSnapshot`

环境快照包含：

- 市场和观察范围涨跌幅；
- 上涨、下跌家数；
- 涨停、跌停、炸板数量；
- 昨日涨停组合的次日溢价；
- 连续分歧天数；
- 转折前市场压力快照；
- 市场宽度从低点改善的幅度；
- 指数是否站上VWAP；
- 跌停负反馈释放比例。

`prior_stress_score` 用于保留转折前的高压环境。否则在市场已经修复的快照里，当前上涨家数会覆盖此前的极端分歧。

## 7. 辨识度量化

辨识度由五个已经标准化到 `0-100` 的分项构成：

```text
recognition =
    25% * height
  + 20% * attention
  + 20% * persistence
  + 20% * influence
  + 15% * resilience
```

建议的数据来源：

| 分项 | 可用数据 |
| --- | --- |
| `height` | 连板高度、阶段涨幅、同类位置排名 |
| `attention` | 成交额、换手率、关注度排名 |
| `persistence` | 近期强势天数、涨停次数、次日溢价 |
| `influence` | 板块带动、跟随数量、题材中心性 |
| `resilience` | 弱市相对强度、板块下跌日抗跌性 |

### 7.1 锚点清晰度

每类锚点按辨识度排序。

默认要求：

- 第一名辨识度不低于 `70`；
- 第一名领先第二名至少 `8` 分。

未满足时返回 `clear=false`，并给出“龙一不清晰”的风险提示。

这一限制用于防止事后看到某只股票走强，再把它反向解释成锚点。

## 8. 主动与被动强弱

### 8.1 相对环境收益

```text
relative_return =
    stock_return
  - 0.5 * scope_return
  - 0.5 * market_return
```

该表达式不是最终统计模型，只是V1的可解释起点。

### 8.2 主动走弱

主动走弱综合：

- 相对环境收益显著为负；
- 价格位于VWAP下方；
- 炸板或跌停；
- 实际表现低于预期；
- 下跌伴随有效成交额。

默认权重：

```text
active_weakness =
    35% * relative_weakness
  + 20% * below_vwap
  + 20% * broken_or_limit_down
  + 15% * expectation_failure
  + 10% * selling_liquidity
```

### 8.3 主动走强

主动走强综合：

- 相对市场和板块更强；
- 位于VWAP上方；
- 涨停或接近涨停；
- 有同板块标的跟随；
- 有足够成交额。

默认权重：

```text
active_strength =
    25% * relative_strength
  + 15% * above_vwap
  + 30% * limit_up_confirmation
  + 15% * sector_followers
  + 15% * liquidity
```

### 8.4 被动走弱保护

如果市场和板块跌幅显著大于个股跌幅，个股的相对收益仍可能为正。此时即使出现炸板，也不能自动判定旧锚主动失效。

单元测试必须持续覆盖这一反例。

## 9. 市场压力与环境转折

### 9.1 市场压力

```text
market_stress =
    25% * down_breadth
  + 20% * limit_down_pressure
  + 20% * broken_board_rate
  + 20% * previous_limit_up_loss_effect
  + 15% * consecutive_stress_days
```

如果 `prior_stress_score` 更高，则使用前序压力，保留“先有充分分歧，后有修复”的时间关系。

### 9.2 环境转折

```text
environment_turn =
    30% * breadth_improvement
  + 15% * index_strength
  + 20% * scope_strength
  + 15% * index_above_vwap
  + 20% * limit_down_release
```

环境转折不是单纯指数上涨，还必须尽量观察市场宽度和负反馈释放。

## 10. 大拐点设计

### 10.1 结构条件

大拐点由四部分构成：

1. 前面存在连续、高强度分歧；
2. 最强旧赚钱效应锚或旧负反馈锚充分出清；
3. 环境由继续恶化转向改善；
4. 出现辨识度清晰、主动性足够的新承接物。

### 10.2 出清评分

旧锚出清综合：

- 连续跌停；
- 近期大幅回撤；
- 跌停打开；
- 有效成交额释放；
- 主动走弱。

系统在旧赚钱效应锚和旧负反馈锚中选择出清证据更强的一方。

### 10.3 候选与确认

加权总分达到候选阈值，只返回：

```text
status = candidate
```

这表示“大拐点可能即将出现”，不表示已经发生。

只有总分和四个独立门槛全部通过，并且新承接物锚点清晰，才返回：

```text
status = confirmed
```

### 10.4 大拐点因子

```text
big_inflection =
    25% * market_stress
  + 25% * old_anchor_clearance
  + 20% * environment_turn
  + 30% * new_carrier_strength
```

默认阈值集中在 `config.go` 中，必须经过历史样本和模拟盘重新校准。

## 11. 小拐点设计

V1支持两类小拐点。

### 11.1 高低切 `high_low_switch`

条件包括：

- 旧赚钱效应锚清晰；
- 旧锚相对环境主动走弱；
- 新承接物开始主动；
- 新承接物具备一定辨识度和可交易性。

```text
small_inflection =
    35% * old_anchor_active_weakness
  + 35% * new_carrier_strength
  + 15% * new_carrier_recognition
  + 15% * environment_tradability
```

### 11.2 个股自身修复 `individual_reversal`

适用于：

- 前一状态主要由市场拖累，被判断为被动走弱；
- 当前个股相对市场和板块主动修复；
- 个股有足够辨识度和主动性。

该类型不要求存在另一只旧赚钱效应锚，因为对照物是个股自己的上一状态和环境锚。

### 11.3 小拐点限制

输出必须保留提示：

- 小拐点是局部提前尝试；
- 不默认产生新周期；
- 低辨识度标的可能只是随机承接；
- 后续需要用预期锚验证，而不是无限格局。

## 12. 输出结构

评估结果包含：

- `market_stress_score`；
- `environment_turn_score`；
- 每个候选的辨识度、主动走弱、主动走强和出清得分；
- 每类锚点的第一名、第二名、分差和清晰度；
- 大拐点与小拐点的状态、类型、总分和因子；
- 旧锚和新承接物代码；
- 解释性证据；
- 风险和数据限制；
- `primary_signal`。

## 13. HTTP接口

```text
POST /api/v1/strategy/inflections/evaluate
```

接口当前接收标准化快照，不会自动抓取全市场实时数据。

请求体限制为2 MB，拒绝未知字段，业务校验错误返回 `400`。

完整请求示例见 [`inflection-engine.md`](./inflection-engine.md)。

## 14. 配置策略

所有默认权重和门槛集中在：

```text
backend/internal/strategy/inflection/config.go
```

原则：

- 代码中不分散魔法数字；
- 默认值只是初始假设；
- 回测参数和生产参数应带版本号；
- 每次参数调整必须保留样本区间和原因；
- 不允许只根据单个成功案例修改权重。

## 15. 测试设计

当前已覆盖：

1. 旧负反馈充分释放、新核心主动的大拐点；
2. 旧赚钱效应锚主动走弱后的高低切小拐点；
3. 被大盘拖累不能误判为主动走弱；
4. 个股上一状态被动走弱后的逆势修复；
5. 龙一、龙二得分过近时锚点模糊；
6. HTTP接口正常响应；
7. HTTP接口拒绝未知字段。

后续需要增加：

- 缺失数据；
- 一字板不可成交；
- 跌停无法退出；
- 市场宽度虚假修复；
- 孤立涨停无板块跟随；
- 预期大拐点最终失败；
- 不同涨跌停制度；
- 历史回放一致性。

## 16. 实时化路线

### 阶段一：历史日线回放

- 建立每日市场压力；
- 建立每类锚点候选；
- 保存每日评估结果；
- 统计次日、三日、五日表现。

### 阶段二：分钟级特征

- 分钟K线；
- VWAP；
- 市场宽度低点和改善幅度；
- 涨停、炸板、跌停打开时间；
- 新承接物出现顺序。

### 阶段三：预期锚

买入或产生信号时保存：

- 预期市场地位；
- 预期开盘表现；
- 允许的VWAP偏离；
- 需要的板块跟随；
- 明确失效条件。

### 阶段四：成交回放

- T+1；
- 排板和真实可成交量；
- 跌停退出；
- 滑点与费用；
- 仓位和容量；
- 连续亏损暂停。

### 阶段五：前端页面

新增“拐点监控”页面，展示：

- 当前主信号；
- 大、小拐点候选和确认；
- 环境锚、旧锚、新承接物；
- 主动/被动强弱；
- 因子证据和风险；
- 历史信号回放。

## 17. 验收标准

系统进入真实试运行前，至少满足：

- 同一历史快照能够稳定复现相同结果；
- 所有输入字段都有明确来源和更新时间；
- 所有信号能够解释到具体因子；
- 锚点选择使用当时可用数据，不含未来信息；
- 一字板和跌停等不可成交状态进入回测；
- 成功和失败信号全部保存；
- 走步验证区间与调参区间隔离；
- 页面明确显示 `candidate` 与 `confirmed` 的区别。

## 18. 未决问题

1. 辨识度应在全市场、同板块还是同涨跌幅制度内排名？
2. 市场压力应使用固定阈值还是滚动历史百分位？
3. 旧负反馈锚是否允许同时存在多个？
4. 新承接物成为新锚点需要持续多长时间？
5. 如何区分板块真实共振和同一消息造成的瞬时脉冲？
6. 大拐点的确认时点如何避免已经无法成交？
7. 个股、板块、市场多级信号冲突时如何排序？
8. 预期锚应该由规则生成还是由交易计划显式输入？
