## #33 数据源健康度是静态值

确认存在。此前 `/api/v1/sources` 固定返回六个正常源和一个异常的 Tushare，并给静态结果添加当前检测时间。

- 已接入的开盘啦、东方财富、新浪、腾讯、财联社并行执行轻量接口探测，整体设置 4 秒超时，检测结果缓存 1 分钟。
- `checked_at` 保留真实探测时间，命中缓存不更新时间；请求取消不缓存为故障。
- Tushare 和 TradingView 在当前后端均未接入，标记为预留、未启用。不读取 Token 来伪造可用状态，也不计入健康度分母或异常提醒。
- 前端统一区分检测通过、检测失败、尚未检测和未启用。轻量探测通过不代表该源所有接口均可用。

## #34 未运行被误报完成，运行中任务无法回收

确认两项问题均存在。

- 查看结果按 `idle`、`waiting`、`running`、`succeeded`、`failed` 展示后端文案，只有完成但缺失结果时才提示缓存不可用。
- 重启后无对应内存任务的 `running` 记录会持久化为中断失败；有有效的新结果时恢复成功。
- 任务执行仍有 6 分钟上下文期限；状态读取同时检查执行上下文及 15 分钟未更新时间的兜底条件。
- 回收时取消执行并移除对应运行实例。旧实例不能覆盖重试任务的状态或写入迟到结果。

## #35 非交易日验证、选中日期及核验日期

确认选中日期不同步、等待核验日与缺少总结混淆、行情日期未校验的问题存在。不过 Issue 对默认查询的部分解释不符合当前代码：后端已经通过 `LatestDailySummaryBefore` 查找最近已保存总结，并非仅查询自然日的昨天。

- 验证读取、状态查询、启动请求跟随复盘摘要选中的日期，切换日期时隐藏旧日期结果并忽略迟到响应。
- 核验日使用与总结一致的本地 A 股交易日历，包括周末和已维护的交易所节假日。
- 例如 2026-10-23 的复盘，核验日是 2026-10-26（周一）；15:00 收盘前明确提示等待，并禁用启动按钮，保留查看总结入口。
- 后端同样拒绝提前启动，不能仅绕过前端禁用状态就运行。
- 采集结果必须对应紧接总结日的下一交易日，拒绝同日、非交易日、更晚交易日、盘中采集，以及日期冲突的指数、个股、涨停梯队或盘面快照。不再将缺失日期伪装为今天。
- 历史情绪日期不匹配时排除该情绪数据；已有错误日期的验证缓存不再作为有效结果展示。
- 验证指数仅使用 A 股市场，避免把美股等不同交易时区的数据混入 A 股核验日。
- 当前采集器不支持任意历史核验日行情回放。如果当前行情已越过目标核验日，会明确拒绝，而不是拿今天的数据验证过去的“明日”判断。

## #25 Windows 11 打开后无界面

报告只有 Windows 11、版本 1.5.5 和“无界面”，没有启动日志。当前环境为 macOS，不能声称已经复现并彻底修复报告者机器上的原始故障。

代码核查确认存在相关缺陷：创建窗口前等待全部服务和后端启动；任何必需服务启动失败只记录日志然后退出；健康检查单次网络请求没有期限，可能超过总等待时间而不返回。

- 现在先创建并持有主窗口，展示启动页，再启动服务。
- 启动失败保留错误界面，展示已脱敏的失败原因、日志目录及打开目录入口，不再静默退出。
- 窗口自身创建失败时提供原生错误对话框。
- 后端健康请求有严格期限，后台进程启动失败或退出会尽快中止等待。
- Windows 子进程不弹控制台窗口；关闭启动窗口后不再加载应用页面。
- 新增模块加入打包白名单，并覆盖启动顺序、失败页面、错误转义、敏感信息脱敏、超时和子进程错误的回归测试。

原始 Windows 故障仍需 Windows 安装包实机验证，或报告者提供 `desktop.log` / `backend.log` 后确认根因。此次不据此关闭 Issue。
