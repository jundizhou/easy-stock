# 真实 AI 持仓优化评估

当前版本为v23 / 提示v31。重点回归：同批部分补丁失败不丢成功股票，服务重启只补缺项，A/B与每条比较独立保存，恢复不重置时间或纠错预算，代码排序只复评一个配置且最多一次有实质变化的改进。历史版本“一次格式修复”的描述由[现行规则](portfolio-investment-selection-design.md#2026-10-07分块检查点有界纠错与集中复评v23--提示v31)替代。

普通 `go test` 不调用真实模型。`TestLivePortfolioOptimizationEvaluation` 显式启用后，运行实际候选收集、代码筛选、24小时研究复用、模型方案、程序求解和匿名独立复评。测试不应用目标持仓，也不更新原始巡检和研究库。

## v23 验证记录

使用隔离保存的8份研究与冻结行情，真实调用 `glm-5.3-flash`：3分51秒完成，独立评分51→72，股票总仓位100%、现金0%，累计替换64%、保留36%。程序产生3个可行备选，选定其中1个复评；没有进入第二轮。共5次模型调用：方案、比较引用补丁、补丁格式修正、A/B复评、A侧行业表述修正。行业表述修复前后A的四维评分完全一致，B及其他已通过块保持原文；未采用新评分样本。结果为需等待条件的方案。

这次实测暴露出待补项的存储元数据被模型抄回输出，导致额外格式修复；现已从模型输入中移除这些元数据，并增加回归保护。随后用完整真实响应记录离线恢复，零模型调用还原相同持仓、A/B评分及采纳结果。该实测验证冻结研究后的生成、修复、求解与复评链路，不代表实时采集耗时或每次都能达到相同分数；没有修改真实持仓和生产历史。

自动回归覆盖部分补丁成功、服务重启、缓存恢复、评分冻结、最多4次纠错、连续同错3次停止、异常中断耗时补记、预算耗尽后显式新建任务、统一程序排序，以及进度接口不传输模型正文。

## 准备与运行

从本机应用数据做 SQLite 一致性备份，放入 Git 忽略的私有目录，例如 `.runtime/portfolio-live-evaluation`。目录权限0700、文件0600；提供 `portfolio.db`、`research.db`、`settings.json` 和 `hermes/` 配置、环境文件及能力缓存。隔离设置需关闭通知和自动巡检，不打印凭据或完整配置。选择24小时内成功、四维完整且个股研究有效的巡检ID。

在仓库根目录设置以下环境变量后运行：

```sh
EASY_STOCK_LIVE_PORTFOLIO_EVALUATION=1 \
EASY_STOCK_EVALUATION_DIR="$PWD/.runtime/portfolio-live-evaluation" \
EASY_STOCK_EVALUATION_SOURCE="$taskInspectionID" \
EASY_STOCK_EVALUATION_OUTPUT="$PWD/.runtime/portfolio-live-evaluation/result.json" \
EASY_STOCK_EVALUATION_CALLS="$PWD/.runtime/portfolio-live-evaluation/calls" \
EASY_STOCK_REPLAY_HERMES_ROOT="$PWD/desktop/resources/hermes-runtime" \
EASY_STOCK_REPLAY_CODEX_ROOT="$PWD/desktop/resources/codex-runtime" \
go -C backend test ./internal/httpapi \
  -run '^TestLivePortfolioOptimizationEvaluation$' -count=1 -v -timeout 30m
```

`taskInspectionID` 是准备好的巡检ID。测试使用配置中的真实模型，会产生该模型的调用用量。每30秒保存任务状态；私有诊断文件保留业务输入和原始输出，日志只显示阶段、字节数和耗时。

## 验收与迭代

先固定验收口径，再运行模型。自动校验候选最多8选6、最终行业不同、研究有效、总仓位及现金守恒、累计替换最多70%、实际改善和独立复评采纳。70分仍为优化目标；按用户最新要求，完整搜索后65–69分、较同次复评原组合提升至少5分且四维均不低于50分的方案，可作为明确标注的备选。少于6个合格候选不补劣质标的。

还需检查投资内容：主营、增长、估值、时机、组合用途、实际风险及机会成本具体；反对事实保留；不同报告期和财务口径不混用；无估值字段不称便宜；不同目录行业不等于低相关；未选原因和等待/退出条件可观察。资料时间应按交易日历判断，假期的最近交易日不自动视为过期。

解析、引用、时间预算和范围冲突分别记录，不能包装成“AI建议原仓不动”。只根据可复现问题修改代码并重测，保留每轮失败和成功记录。不通过反复采样选出高分、强制调整或乐观结果；有依据的保持原仓可以完成评估，但不计作达到70分的优化成功。

方案生成使用模型支持的low思考上限，独立复评使用medium上限；不改用户全局设置。首轮方案输入22KiB、改进方案及复评24KiB、所有调用含修复最多32KiB；阶段8分钟，总运行24分钟。修复超限时删重复格式示例，并将重复股票/投资字段无损压成列定义与值；缺少字段索引明确记录，全部事实、原叙述与约束保留；不截断或猜测模型结论。

旧协议回放时，偏好权重合计必须等于固定股票总仓位，不允许程序默默补齐缺失的15%等大额差距。若其他投资内容通过且仅合计不正确，唯一一次修复只返回每股整数权重；股票、区间、角色、投资理由、引用和条件在内存中冻结。修复输入列出程序实际上下限（原范围、增持权限、锁定、单票风格上限）。完整合计正确且在原范围内的补丁，可以用原求解器校正最多1个百分点的分配（绝对差合计≤2）；最终仍满足全部交易、总仓位及累计替换规则，修正逐股公开记录。较大冲突、未知股票、超原区间或不完整合计仍失败。

一种已确认的模型结构错误可无模型调用校正：首方案`allocations`只含一股，后续完整股票对象错落在`alternatives`，可选尾部只有`keep_reason`。只重新嵌套，逐项数值与文本保持原样，随后全量校验；真实多方案、未知尾文或不完整行拒绝猜测。

资金配对优先按已经校验的结构化投资比较，用整数最大流匹配实际减持→实际增持；各腿资金守恒且每份资金只配对一次，不改变选股和权重。没有比较支持的剩余资金去向继续公开，不能伪装成投资改善。

仅对明确的临时连接/502/503/504等传输错误重试一次，输入不变、阶段与总预算不重置，也不消耗格式修复次数。鉴权、配额、模型名、未知错误和宿主阶段/首响应/空闲超时不自动重试；上游明确连接超时仅在宿主预算尚余时可重试一次。低分不重复采样同一投资结论；新版允许按具体缺陷实质改进仓位一次，独立复评仍不接收目标分数或首轮反馈。

## 顺序稳定性

成功后复制任务JSON，保持冻结资料、方案、目标、资金配对和条件，清除临时评估状态，把计划设为 `pending_review` 并交换 `assessment_order`。显式启用 `TestLiveSavedOptimizationReview`，通过 `EASY_STOCK_OPTIMIZATION_AUDIT`、`EASY_STOCK_REPLAY_SETTINGS`、`EASY_STOCK_REPLAY_HERMES_HOME`、运行时目录及 `EASY_STOCK_REPLAY_OUTPUT` 提供隔离输入。只复评，不重选股或重做个股研究。

比较交换前后的实际偏好、资金方向及理由，不要求分数完全相同。若因为A/B标签改变偏好，应排查顺序偏差并记录，不能隐藏较差的一次。一次真实测试只说明这组冻结输入的流程和判断通过验收，不证明所有输入必然成功或未来收益。

## 同一失败记录的回归

对已保存的任务、原方案输出及原权重补丁，设置`EASY_STOCK_OPTIMIZATION_RESPONSE`与`EASY_STOCK_OPTIMIZATION_PATCH`，启用`TestSavedPreferredWeightPatchProjection`进行完全离线的内容不变/数学边界校验。完整隔离回归则显式启用`TestLiveSavedOptimizationReview`：同两个原始输出只回放，不新增方案调用；后续独立复评使用真实模型。`EASY_STOCK_REPLAY_CALLS`可保存原始业务输入/输出，`replayed`明确标记缓存来源，不重复记录旧调用用量。

这是新的隔离测试任务：清除其临时修复标记，再按正常服务路径消费同一修复，不修改生产历史或生产恢复次数。结果中的回放耗时不是原模型生成耗时；最终报告须分别列出原生成/补丁耗时、当前真实复评耗时及历次失败。顺序复评只交换A/B，不更改目标权重与条件。

已确认的内容错误也需回归：不能把包含非芯片业务的组合称为全芯片资产，不能把缺乏估值数据说成便宜，不能把归母利润全部视为主营。程序针对已发现的明确错误做校验；这不等于可以自动证明全部自然语言推断。人工审计还要检查原报告、事实口径、实际资金方向及未兑现条件。

## 冻结研究上的新规则实测

在隔离环境启用`EASY_STOCK_OPTIMIZATION_NEW_PROPOSAL=1`，与`EASY_STOCK_LIVE_OPTIMIZATION_REVIEW=1`搭配。`EASY_STOCK_OPTIMIZATION_AUDIT`提供冻结研究/行情的历史任务，清除仅本次隔离任务的旧方案与修复标记；方案、改进及复评全部真实调用，不回放旧方案。不修改历史研究完成时间，不将旧行情声称为新行情，不更新用户持仓。每次保存新的结果和调用目录，70分以下须区分合格备选与未达标，不能称达到70分目标，也不能修改或隐藏旧结果。

单元回归覆盖70目标、65–69备选的改善幅度和四维下限、低于65拒绝、模型虚报总分、仅改进一次、资料研究不重复、累计基线不重置、同目标不重复评分、历史保存以及应用API/UI双重拦截。


## 2026-10-07：主动搜索、评分备选与稳定输出

该轮版本为`portfolio-optimization-v15` / `portfolio-optimization-prompts-v23`。方案模型输出`weight_mode=program`、每股投资行动和min/max范围，不再重复输出preferred_weight、suitable_for_increase、suitability_reason。程序依allocate/wait/hold/reduce派生资金权限，在原交易、条件、总仓位和累计变动约束内搜索整数比例；公开报告仍保存完整命名字段及代码计算的参考权重。历史完整协议继续严格校验，不自动消除原本相互矛盾的字段。

65–69分是搜索70分目标结束后的备选，不使搜索提前停止。必须较同次匿名复评原组合提升至少5分、四维均不低于50分、独立偏好目标、存在真实改善且风险/资金校验通过。最多保存一个已验证备选跨范围改进复用；后续得分更低不丢失它。后续模型失败或期限耗尽时可保留已有合格备选并披露中断，用户主动停止仍停止。没有合格备选时不将失败包装成保持原仓的投资建议。应用接口和界面均重新计算四维加权分，不能虚报总分或降低原组合分数制造改善。

引用处理保留原分数：允许本组事实的规范key和确定的JSON路径别名；相反组、未知事实和缺测字段继续拒绝。assessment未标A/B的比较指标保存为双方真实值，不能任意当成其中一组，也不能覆盖各组原始事实。相关性仅在已有实测对存在时接受交换股票顺序，缺测不推算。现金缺口只计风险承受维度；静态止损覆盖与语义退出计划分别说明。量化结构改善已有独立复算时，不再要求复评另造可选资金配对；仅投资改善仍需真实增权→减权的双方引用比较。

缺少比较引用时唯一一次格式修复只返回引用补丁，股票、投资正文、区间、资金权限、风险分组和原条件冻结。修复不重复发送整篇旧输出，仍共用原阶段和总预算。

## 2026-10-07：方案阶段跨股引用路径兼容

真实失败任务的两次方案调用分别把同一已测相关性引用写成 `<参与股票>.cross.correlation.<股票1>.<股票2>` 与 `cross.correlation.<股票1>.<股票2>`；原事实可用，但方案阶段没有复用独立复评的别名解析，导致耗费一次模型格式修复后仍失败。方案引用校验现统一使用共享解析器，只将实际存在且可用的路径转为规范引用并持久保留，方便逐股引用校验与界面溯源。额外股票前缀仅允许该相关性配对成员；未知、缺测、错误成员、A/B错域及混合来源继续拒绝。引用列表全部通过后才写回，失败列表不部分改写。评分口径、投资内容和仓位约束不变。
