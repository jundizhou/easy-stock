# 持仓优化：新增资金适用性分级方案

方案日期：2026-10-06。状态：已撤回，仅保留设计记录；当前运行规则为 portfolio-optimization-v6。

**本方案已撤回，保留讨论记录。** 用户要求不按证据分档决定持仓及增持。后续以 [投资价值与组合角色选股方案](portfolio-investment-selection-design.md) 为准；本页三档权限及试配资金池限额不再拟实施。

## 1. 要解决的问题

当前新增与增持同时要求整份研究 `sufficient`、决策不是 `no_plan`、同周期且交易资格有效。财务事实已核实，但当天上涨归因不明或没有静态价格方案，也会将股票统一禁止接收资金。原组合满仓且现金固定时，全部标的被禁止接收资金就无法减仓，评分低也只能返回原比例。

新增资金适用性应独立于报告总体证据等级，按本次配置依据和关键缺口判断。原报告的证据等级、结论、生成时间及原用途均保留，不将有限研究改写为充分，也不将“已有仓位可以持有”直接解释为适合增持。

## 2. 先检查硬性限制，再评估配置依据

所有资金接收标的须有成功且在24小时复用窗口内的个股报告，研究周期适用、来源引用有效、报价和成交数据符合最近有效交易日要求。代码候选筛选继续保留ST、上一已完成交易日涨跌停、近20个交易日涨幅超过50%、财务健康及行业分散限制，不因本次放宽而绕过。

以下情况禁止接收新增资金：

- 核心判断缺乏基本依据，或报告无法通过结构与引用校验。
- 关键财务数字或口径冲突未核实，且冲突可能改变盈利健康、估值或本次配置理由。
- 配置理由依赖尚未核实的订单、客户、合同、量产等公司事实，移除该假设后理由不成立。
- 财务恶化、亏损或其他风险使本次增量资金理由不成立；不通过“摊低成本”绕过。
- 真正过期、缺失的报价/成交数据、未知交易资格或已知不可交易限制。
- 缺少有效的配置失效条件，或将待验证事项误标为已经确认。

以下缺口不再单独禁止条件性配置：不知道当天上涨的原因、缺少逐笔资金流、缺少细分板块共振验证、没有静态入场/止损价格、尚无下一季度数据。它们仍保留在报告中；若本次配置理由恰好依赖这些事实，则重新成为必须核实的关键缺口。超短周期依赖盘面时不套用中期财务理由解锁。

每只标的说明本次角色与依据：已核实经营/财务、可复算量价结构、或可检查的组合结构改善。单纯声称“另一行业更安全”“低评分所以换股”不构成资金理由；行业分散与未来相关性分别表述，未知相关性保持未知。

## 3. 三档权限与默认限额

| 权限 | 条件 | 允许行为 |
| --- | --- | --- |
| 正常配置 | 本次配置依据充分、关键缺口不影响依据、资金适用性通过 | 按现有风格上限新增/增持；仍须独立复评 |
| 限额试配 | 总体证据有限，但配置所用事实已核实，剩余缺口的影响被明确限制 | 可生成小比例的条件性新增/增持方案 |
| 不接收新资金 | 有硬性限制或配置依据不成立 | 保留、减持或退出可研究；没有资金接收方时返回不可行 |

限额试配的推荐默认值如下，属于产品风险控制参数，不是经回测证明的最优仓位：

| 风格 | 已有股票累计增持上限 | 新股票目标仓位上限 | 试配股票累计新增资金上限 |
| --- | ---: | ---: | ---: |
| 激进 | 8个总资产百分点/只 | 总资产8%/只 | 初始股票仓位的25% |
| 均衡 | 5个总资产百分点/只 | 总资产5%/只 | 初始股票仓位的15% |
| 稳重 | 3个总资产百分点/只 | 总资产3%/只 | 初始股票仓位的10% |

例如均衡风格原股票仓位80%，试配资金合计最多占总资产12%，总股票仓位仍为80%；现有股票的5个百分点增持上限与新股票5%目标上限均按总资产计算，还要服从单票35%上限。

同一优化链继续以初始基准计算累计净增持和替换额度，不按每次点击重置。已经超过新限额的存量可保留或降低，不允许借本次优化继续扩大超额；评级或限额变化也不能让原组合因存量超额变成无法展示的非法组合。实现时同时记录权限版本、初始权重、当前权重、目标权重和累计资金占用。

新增股票最多2只、总持仓最多10只、总仓位/现金不变、相对初始股票仓位替换不超过70%、至少保留30%原股票仓位重叠，均继续生效。70%是上限，不要求用完。

## 4. no_plan、观察报告和价格计划的处理

不能只通过 `no_plan` 字符串决定权限。配置核验记录结构化原因：数据/交易限制、核心依据不足、财务风险、事件未核实、仅缺静态价格方案、或执行条件待触发。历史报告没有这些字段时，现有方案生成请求依据原文评估并引用依据，不新增一轮完整个股研究。

空的可选 `price_plan={}` 与未提供价格方案区分处理：不补造入场或止损价，按缺少可选静态价格方案处理，原有有效的确认/失效条件仍可用于条件性组合研究。实际填写的无效锚点不能被当作有效价格；价格校验失败要保留具体原因，不静默恢复交易指令。

原研究明确反对接收新资金，或等待的是影响核心事实的必要披露时，不能当作普通技术条件绕过。若方案使用不同的、已核实的配置依据，须明确说明为何适用于本次组合，并由独立复评核验；不能推翻原报告后隐去原异议。

未满足的量价/披露条件允许进入目标组合的条件性比较，但必须标为“条件满足后调整”。该结果是待条件验证的配置研究，当前实际持仓仍为原组合；不声称已经买入、已经清仓或可以立即执行。未知止损仍为未知，不默认零风险。

## 5. 执行流程与速度

1. 复用24小时内报告，刷新必要报价，由代码检查硬性限制和计算各风格的资金上限。
2. 在现有方案生成模型请求内逐股评估新增资金适用性，返回配置依据、原报告异议、关键/非关键缺口、权限档位、确认/失效条件和资金来源。新字段引用原来源编号；代码校验事实和上限，不以模型一句“可以增持”解锁。
3. 程序按1%仓位精度求解一套目标组合，同时检查试配资金池、风格上限、70%替换及总仓位守恒。
4. 用共享事实对原/目标组合做独立复评。至少有一项可复算的原问题改善；分数提升本身不够。均衡与稳重的风险承受评分不能下降，已知重大风险暴露不能扩大。明确披露新增试配带来的不确定性，不能因目标组合包含更多有限研究就宣称证据覆盖提升。
5. 展示原持仓→目标持仓及条件状态。无合格方案仍说明具体阻碍，但不把无调整包装为原组合获得推荐。

不增加逐股AI适用性调用，不重跑复用报告，也不为追求某个分数循环生成方案。继续保持方案与独立复评各最多8分钟、单次总计最多24分钟；修复计入对应阶段预算。新权限版本纳入任务指纹，历史结果保留，重新优化不回放旧的全禁止结果。

## 6. 本次六只股票的设计检验

以下仅用于验证规则如何分流，不代表已经得出新的买卖建议：

- 星宸科技：修正空可选价格计划的误降级后，重新核验增量资金依据；财务充分不自动表示适合加仓，原新仓保留意见仍交独立复评。
- 翱捷科技：扣非仍亏、经营现金流为负以及订单缺原文，当前增量资金依据不足，继续严格限制。
- 行云科技：可核实的财务修复与未核实合同分开评估；依赖合同的加仓仍受限，其他配置理由须解释高负债与小利润体量，至多限额试配或等待核实。
- 慧智微：亏损扩大且原研究反对方向性持有，不因放宽规则允许摊低成本增持。
- 石头科技：退税归类是否改变盈利健康须核实或做明确的保守情景核验；缺当天上涨归因本身不再否决。核心盈利依据成立后才可进入限额试配。
- 北京银行：银行同业归因不明可列为待验证事项；普通股净利/归母净利和现金流的口径需要明确，不能默认冲突已解决或资产质量良好。配置所用事实成立且没有关键风险阻碍时可进入限额试配，条件待触发时明确标注。

验收重点：有限证据可在上限内产生条件方案；关键缺口继续拦住资金；空可选价格方案不误伤持仓研究；不把有限证据升级为充分；连续优化不能叠加试配预算；固定总仓位、资金配对与70%上限始终有效；未满足条件不标为可立即执行。
