# 持仓巡检的自动上下文压缩

适用于默认持仓巡检评分路径；不改变最多 10 只持仓的产品限制。提示词版本为 `portfolio-inspection-v11`，摘要协议为 `portfolio-compaction-v2`，评分规则不变。实现入口是 `backend/internal/portfolioinspection/scoring_compaction.go`。

## 处理流程

1. 正常构建冻结的事实、决策卡、来源及动作目录。完整提示词不超过 192 KiB 时直接评分，不增加摘要调用。
2. 超出时先核对不可改写部分的最小体积。数值事实、来源编号、交易条件、价格锚点、失效条件、执行限制本身就无法容纳时，在调用模型前返回明确原因。
3. 按可缩减体积从大到小处理标的。达到输入目标就停止，未处理的标的保留原决策卡和来源摘录。若摘要反而增大输入，则保留该标的原输入。
4. 每段都是完整 JSON，保留字段路径和来源归属。只对超长字段进一步切分，优先在句末分段；每段带分段序号、陈述类型及来源编号，不直接切开序列化 JSON。
5. 每个摘要的 JSON 编码长度最多 6 KiB。多个摘要仍过大时继续合并摘要；每轮都必须收敛。摘要不保证语义无损，最终报告固定列出这一限制。
6. 评分与修复使用同一份冻结输入。修复材料或恢复任务的旧输出过长时，丢开旧草稿，带精简的校验反馈重新评估全部冻结证据。这占用原有的评分/修复次数，不新增无限重试。

字节预算是应用层的保守容量控制，不等于提供商的 Token 窗口。不能保证任意模型、任意体积的资料都成功。

## 调用与时间边界

- 单个结构化分片的 JSON 编码长度最多 32 KiB，避免引号、控制字符和 HTML 转义使请求意外膨胀。
- 摘要格式或长度无效时最多重新生成一次；网络错误、鉴权错误和用户取消不由此流程重试。
- 一次任务最多 64 次摘要调用，包括摘要合并和格式修复；所有调用共享四个模型阶段的时间预算。
- 评分仍最多首轮加一次修复。192 KiB 目标为旧输出和修复诊断预留空间；完整修复请求仍检查 256 KiB 上限。
- 使用任务开始时冻结的模型、思考与响应等待配置。每次调用有单阶段截止时间，用户取消可终止后续处理。

这些是失败保护上限，不是预期耗时。正常输入不会触发额外模型调用。

## 检查点与恢复

`portfolio_compaction_checkpoints` 是与评分现场类似的私有 SQLite 表，不出现在任务接口 JSON 中。每条有效摘要以任务 ID 和输入摘要哈希为键保存。哈希覆盖完整分片提示词、摘要协议和冻结的模型配置标识；无法确定模型配置身份时不复用持久摘要。

每段通过格式及长度校验后立即保存，包括取消恰好与有效响应同时到达的情况。无效摘要不保存；摘要可能在语义上遗漏信息，格式通过不代表内容已被程序核实。

恢复任务时将旧任务的摘要检查点复制到新任务。输入或模型配置变化的部分自动重做，未变化部分复用。副本独立，因此删除旧记录不影响新任务。删除某条巡检记录时，在同一事务中删除它自己的摘要检查点和评分现场。

进度消息显示正在处理的标的、已完成段数和复用段数；运行日志仅记录体积和调用统计，原始资料及摘要正文不会因此写入普通日志。

## 验证范围

离线测试覆盖八只大体量持仓、只压缩大报告、结构化字段与来源完整性、Unicode 与 JSON 转义、精确数值、不可压缩部分预检、摘要合并和格式修复、调用上限、取消与恢复、重启后的缓存、模型变更失效、记录删除，以及超长评分修复和超长旧草稿恢复。

模拟模型测试验证编排和约束，不能证明真实模型的摘要召回率或评分一致性。真实组合仍应评估关键反证、来源归属和最终评分的语义质量。
