# 行情总览方案与实现说明（Clean-room 版）

## 实现状态（2026-08-11）

本方案已在独立分支 `codex/market-overview` 完成实现。当前交付包含 11 个可用模块、8 组新 HTTP API、东方财富主数据源、个股资金的新浪降级源、45 秒短时缓存、刷新失败时的最近成功快照降级，以及所有模块到 AI 对话的证据联动。

已实现模块：新闻快讯、市场核心指数、行业趋势强度、行业资金、题材概念、个股资金流入流出、龙虎榜、公告雷达、机构观点、产业透视。页面不使用模拟行情，并统一展示数据来源、抓取时间、陈旧状态和降级原因。

## 1. 方案结论

在现有左侧主导航的「AI 对话」下方新增一级入口「行情总览」，将行情、资金、龙虎榜、公告和研报能力集中为一个独立工作台。

不建议把参考项目的 11 个菜单简单改名、换序后照搬。更合适的做法是保留用户需要解决的问题，重新设计信息架构、领域模型、接口、页面组件和交互，并与 easy-stock 已有的题材、连板、个股分析及 AI 对话形成联动。

目标形态：

```text
趋势题材
短线连板
游资心法
大V复盘日记
个股AI分析
AI 对话
行情总览        <- 新增，位于 AI 对话下方
系统设置
```

「行情总览」内部不使用参考项目的平铺长菜单，而按用户决策流程分为三组：

```text
市场总览
  新闻快讯
  全球温度
  市场核心指数

资金结构
  行业趋势强度
  行业资金
  题材概念
  个股资金流入流出
  龙虎榜

研究信号
  公告雷达
  机构观点
  产业透视
```

## 2. 参考边界与合规原则

参考仓库：[ArvinLovegood/go-stock](https://github.com/ArvinLovegood/go-stock)，核对快照为 commit `50ae57559f60a6176b910e9f363d99fb3367969c`。

参考项目使用 GPLv3，easy-stock 当前使用 PolyForm Noncommercial 1.0.0。为了避免许可证和原创性风险，后续实施必须遵循：

1. 只提取功能需求和用户问题，不复制源代码、组件结构、样式、图标搭配、提示词、文案、接口封装和数据字段命名。
2. 不以“改变量名、改菜单名、打乱代码顺序”作为重构；所有模块根据 easy-stock 的领域模型重新实现。
3. 数据接口由本项目独立调研、独立编写 Provider、独立保存测试样本；不从参考仓库迁移请求参数、解析器或容错逻辑。
4. 不使用参考项目截图、Logo、品牌元素和视觉布局作为直接实现素材。
5. 每个新文件在评审时做来源检查；若确需引入第三方代码，必须单独记录来源、许可证和修改说明。
6. 上游财经数据的可用性不等于允许任意抓取，实施前需确认服务条款、频率限制和商业使用边界。

本方案追求的是独立实现后的功能覆盖，不是隐藏复制痕迹。

## 4. 页面与交互方案

### 4.1 一级导航

- 在 `AI 对话`下方加入 `行情总览`，图标建议使用 `ChartNoAxesCombined` 或 `ChartCandlestick`。
- 路由建议使用 `#market/<view>`，例如 `#market/pulse`、`#market/stock-flow`。
- 默认打开 `#market/pulse`，并记住用户最后一次访问的子模块。
- 侧栏收起时只展示一级图标，二级功能放在内容区，不在主侧栏堆叠 11 个入口。

### 4.2 工作台布局

沿用 easy-stock 当前视觉语言，采用全新布局：

```text
┌ 行情总览标题 / 交易状态 / 数据时间 / 刷新 ┐
├ 市场总览 | 资金结构 | 研究信号          ┤
├ 子模块导航 ─────────────────────────────┤
│ 主内容：表格、走势图、筛选、详情抽屉      │
│                                         │
│ 右侧可选：AI 解读 / 数据来源 / 风险提示   │
└─────────────────────────────────────────┘
```

统一交互规范：

- 所有列表支持搜索、排序、分页和交易日选择。
- 所有数据块展示来源、更新时间、是否陈旧、是否使用降级源。
- 点击股票可进入现有「个股 AI 分析」；点击题材可进入「趋势题材」。
- 每个模块提供「交给 AI 解读」操作，把结构化证据带入 AI 对话，而不是只拼一段自然语言。
- 涨跌颜色、金额单位、空值、休市和错误状态使用全局统一格式。
- 避免复刻参考项目的 NaiveUI 页签、深灰长菜单和同名信息层级。

### 4.3 各模块页面重点

#### 新闻快讯

- 顶部：市场状态、涨跌家数、涨停/跌停、成交额、主线热度。
- 中部：财联社等快讯流，支持来源、重要级别、股票/题材标签筛选。
- 右侧：AI 盘面摘要，明确区分事实、推断、风险和待验证条件。
- 与现有趋势题材、短线连板数据合并生成摘要，不只总结新闻文字。

#### 全球温度

- 按中国、亚太、欧洲、美洲组织指数卡片。
- 展示最新价、涨跌幅、交易状态、更新时间和币种。
- 支持自选重点指数，不把所有指数固定写死在页面中。

#### 市场核心指数

- 默认对比上证、深成指、创业板、沪深 300、恒生、纳指、标普 500。
- 支持日 K、区间收益、波动率、最大回撤和相对强弱对比。
- 指数目录走后端配置，不在前端组件中硬编码大量页签。

#### 行业趋势强度

- 支持当日、5 日、20 日三个窗口。
- 指标包括涨跌幅、上涨广度、成交额变化、主力净流入、领涨股、持续性。
- 点击行业可联动行业资金和关联个股。

#### 行业资金 / 题材概念

- 同一套资金流组件，不同维度参数驱动，避免重复实现两套图表。
- 展示当日净流入、5 日累计、连续流入天数、流入加速度和领涨标的。
- 提供“资金强但价格弱”“价格强但资金弱”等背离标记。

#### 个股资金流入流出

- 支持净流入额、净流入率、主力/超大单/大单/中单/小单维度。
- 默认过滤停牌、ST、成交额过低和数据缺失标的。
- 点击一行打开详情抽屉，展示资金趋势、K 线、所属题材和 AI 分析入口。

#### 龙虎榜

- 按交易日展示上榜股票、原因、买入、卖出、净额、机构席位数量。
- 详情展示营业部明细、机构专用席位和重复活跃席位。
- 不自动把龙虎榜等同于利好；AI 解读必须同时列出正反证据。

#### 公告雷达

- 支持股票、关键词、公告类型和日期过滤。
- 分类包括业绩、回购增持、减持、重组、分红、监管、风险提示等。
- AI 摘要保留原文链接和关键数字，禁止只输出无出处结论。

#### 机构观点

- 展示机构、分析师、评级、目标价、盈利预测、发布时间和报告标题。
- 支持观察评级上调/下调、目标价变化和机构观点分歧。
- 报告全文不可用时，只展示上游明确提供的摘要字段，不伪造正文。

#### 产业透视

- 以行业关键词、行业目录或当前题材为入口。
- 聚合行业报告、公告、题材强度和核心公司，形成证据目录。
- AI 输出固定为：行业现状、景气驱动、产业链、受益环节、反方证据、验证指标。

## 5. 与 AI 对话的融合

行情总览不是独立的数据陈列页，而应成为 AI 对话的证据入口。

建议新增统一的 `MarketContextPack` 概念：

```json
{
  "kind": "industry_momentum",
  "title": "半导体行业趋势强度",
  "as_of": "2026-08-11T15:00:00+08:00",
  "filters": {"window": "5d"},
  "facts": [],
  "sources": [],
  "warnings": []
}
```

用户点击「交给 AI 解读」时：

1. 当前页面把筛选条件和选中对象交给后端。
2. 后端重新组装结构化事实，避免信任前端拼接的数据。
3. Hermes 收到证据包、来源、时间和风险提示。
4. AI 对话保留证据包 ID，后续追问可以继续引用同一快照。
5. 数据已过期时明确提醒用户刷新，不把历史数据描述成实时数据。

Provider 只负责上游请求和解析；`marketcenter` 负责统一模型、缓存、聚合、排序和降级；HTTP 层只做参数验证和输出。

### 6.2 API 草案

| Method | Path | 用途 |
| --- | --- | --- |
| GET | `/api/v1/market/overview` | 市场总览和交易状态 |
| GET | `/api/v1/market/indexes?scope=global` | 全球温度 |
| GET | `/api/v1/market/indexes?scope=core` | 核心指数与对比数据 |
| GET | `/api/v1/market/industries?window=5d` | 行业趋势强度 |
| GET | `/api/v1/market/flows?dimension=industry` | 行业资金 |
| GET | `/api/v1/market/flows?dimension=theme` | 题材概念 |
| GET | `/api/v1/market/flows?dimension=stock` | 个股资金流入流出 |
| GET | `/api/v1/market/billboard?trade_date=YYYY-MM-DD` | 龙虎榜 |
| GET | `/api/v1/research/announcements` | 公告雷达 |
| GET | `/api/v1/research/institution-reports` | 机构观点 |
| GET | `/api/v1/research/industries` | 产业透视资料索引 |
| POST | `/api/v1/ai/market-context` | 生成 AI 可引用的市场证据包 |

所有响应继续使用现有 `SourceMeta` 约定，至少包含：

- `source`
- `source_url`
- `fetched_at`
- `latency_ms`
- `stale`
- `trade_date`
- `fallback_reason`

### 6.3 统一模型建议

- `MarketIndexSnapshot`：指数代码、市场、价格、涨跌、开闭市状态。
- `IndustryMomentumItem`：行业强度、区间收益、上涨广度、资金和领涨股。
- `FundFlowItem`：对象类型、净流入、分单结构、累计值、连续性。
- `SeatActivityItem`：股票、上榜原因、机构席位、营业部买卖和净额。
- `ResearchItem`：内容类型、标的、机构、标题、摘要、时间、原文地址。
- `MarketContextPack`：AI 使用的结构化证据快照。

前端不得直接依赖东财、腾讯等上游字段名。

## 7. 数据源与缓存策略

| 数据 | 首选策略 | 建议刷新 | 降级方式 |
| --- | --- | --- | --- |
| 市场快讯 | 复用 CLS Provider，后续增加第二来源 | 15-30 秒 | 最近成功快照 |
| 全球指数 | 独立实现腾讯或其他许可允许的源 | 交易中 3-5 秒 | 30 秒缓存/备用源 |
| 核心指数 K 线 | 复用 K 线基座并扩展指数代码 | 分钟或按需 | 最近成功 K 线 |
| 行业趋势强度 | 行业行情 + 本地计算 | 30-60 秒 | 上一快照并标 stale |
| 行业/题材资金 | 独立资金 Provider + SQLite 历史 | 60 秒 | 当日最近成功值 |
| 个股资金 | 按榜单请求，详情按需加载 | 60-120 秒 | 不跨交易日伪装实时 |
| 龙虎榜 | 盘后或低频增量同步 | 5-15 分钟 | 上一交易日 |
| 公告/研报 | 增量游标或发布日期同步 | 10-30 分钟 | 本地索引 |

关键要求：交易时段感知、全局请求去重、并发限制、指数退避、SQLite 持久缓存、重启不突破上游频率限制。

## 8. 实施阶段

### 阶段 0：规格冻结与洁净边界

- 固定本方案中的命名、路由、字段和交互，不以参考项目源码作为实现规范。
- 为每个数据源保存独立调研记录、响应样本和字段解释。
- 确认第三方服务的使用条款、请求频率和发布限制。

### 阶段 1：行情总览壳层与已有能力接入

- 新增「行情总览」一级入口和三级分组导航。
- 先接入现有 CLS 快讯、题材总览、板块资金字段和 K 线能力。
- 打通“查看股票/题材”和“交给 AI 解读”两个跨工作台动作。

验收：不增加新数据源也能形成可用的新闻快讯 MVP。

### 阶段 2：指数与行业趋势强度

- 增加全球指数 Provider 和统一指数目录。
- 扩展 K 线模型对 A/H/美指数的支持。
- 新增行业 1/5/20 日动能榜及详情页。

验收：市场核心指数、行业趋势强度可独立使用，具备 stale/fallback 状态。

### 阶段 3：资金结构

- 建设统一资金流模型和历史缓存。
- 实现行业资金、题材概念、个股资金流入流出。
- 增加背离、连续性和加速度等本项目自有指标。

验收：三个资金模块共享同一数据和组件体系，不出现三套重复代码。

### 阶段 4：席位与研究信号

- 实现龙虎榜、公告雷达、机构观点和产业透视。
- 增加本地索引、去重、原文链接和搜索能力。

验收：所有研究结论可以回到原始来源；缺失全文时不生成伪内容。

### 阶段 5：AI 证据闭环

- 落地 `MarketContextPack`。
- 对接 Hermes 会话续接、证据引用和过期提示。
- 建立模块级提示模板，但模板只定义输出结构，不写死投资结论。

验收：AI 回答能展示数据时间、来源、事实/推断边界和反方证据。

## 9. 测试与验收标准

### 功能验收

- 「行情总览」确实位于「AI 对话」下方。
- 11 项能力全部有独立入口或明确的合并入口，不丢功能。
- 页面刷新、切换和桌面应用重启不会重复轰炸上游接口。
- 股票、题材、指数可以跨模块跳转，筛选状态可恢复。
- AI 解读只使用带时间和来源的证据包。

### 工程验收

- Provider 解析全部有固定样本单元测试。
- 聚合、排序、分页、缓存和降级有服务层测试。
- 外网 live test 默认关闭，失败时能区分鉴权、限流、超时和解析错误。
- 前端有路由、加载、空态、错误态、stale 状态和关键交互测试。
- 新代码通过许可证和相似代码检查，不引入 GPLv3 源码片段。

### 产品验收

- 15 秒内能回答“现在市场整体怎么样”。
- 30 秒内能从行业强弱定位到题材、个股和资金证据。
- 公告、研报和龙虎榜结论都能一键回到原文或原始数据。
- AI 输出不把延迟数据描述成实时数据，不把推断描述成事实。

## 10. 建议优先级

推荐先做：

1. 行情总览壳层与新闻快讯。
2. 市场核心指数、行业趋势强度。
3. 行业/题材/个股统一资金流。
4. 龙虎榜、公告雷达、机构观点、产业透视。
5. 完整 AI 证据包和跨会话引用。

这样第一阶段就能使用现有能力交付价值，同时将新增数据源和高风险抓取模块后置，避免一次性铺开 11 个互相孤立的页面。
